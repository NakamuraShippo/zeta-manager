# zeta-manager

**Zetaの会話ログ管理と、Markdownによるロアブック作成を支援するツールです。**

[Zeta Web版](https://zeta-ai.io/)で読み進めた会話を保存・コピーしたり、あらかじめ用意した設定文をロアブックへまとめて入力したりできます。パソコン用のChrome版と、iPhoneのSafariで使うiOS版があります。

会話ログの取得・コピー・ロアブック入力に、AIサービスのAPIキーは必要ありません。

> **LLM要約機能はデバッグ中・動作未保証です。** 接続、会話の送信、要約結果の取得を含めて確認中です。

## zeta-managerでできること

### 会話ログを残す

会話ページをスクロールすると、表示された範囲を自動で取得します。過去の会話をまとめて取得する「全履歴を同期」や、メモなどへ貼り付けるためのコピーにも対応しています。Chrome版では、保存したログの一覧・閲覧・削除もできます。

### ロアブックの入力をまとめて行う

Markdownファイルに書いた「題名・キーワード・内容」を読み込み、ロアブックの各項目に入力します。空の入力欄を利用し、不足する分だけ項目を追加します。入力済み項目を保持し、最大50項目まで扱えます。

| 機能 | Chrome版・パソコン | iOS版・Safari |
| --- | :---: | :---: |
| 表示された会話の自動取得 | ○ | ○ |
| 全履歴を同期 | ○ | ○ |
| 会話のコピー・自動保存 | ○ | ○ |
| 保存ログの一覧・閲覧・削除 | ○ | — |
| Markdownからロアブックへ入力 | ○ | ○ |
| LLMによる要約 | デバッグ中・動作未保証 | — |

<a id="chrome-install"></a>
## Chrome版のインストール

**Node.jsのインストールやコマンドの入力は不要です。** 完成済みZIPを展開してChromeに登録します。

### 1. Chrome用ZIPをダウンロードする

[**Chrome版をダウンロード（zeta-manager-chrome.zip）**](https://github.com/NakamuraShippo/zeta-manager/releases/latest/download/zeta-manager-chrome.zip)

リンクをクリックしてZIPを保存してください。[リリース一覧](https://github.com/NakamuraShippo/zeta-manager/releases)から取得する場合は、Assets内の **zeta-manager-chrome.zip** を選びます。

**Code → Download ZIP** や **Source code (zip)** は開発者向けのソースコードです。通常のインストールでは使いません。

### 2. ZIPを展開する

1. ダウンロードしたZIPを展開します。Windowsは右クリック → **すべて展開**、MacはZIPをダブルクリックします。
2. 展開したフォルダを、ドキュメントなどの保管場所へ移します。
3. フォルダ内に `manifest.json`、`content.js`、`service-worker.js`、`options.html`、`options.js` があることを確認します。

ZIPの中を表示するだけでなく、必ず展開してください。導入後もChromeがこのフォルダを使うため、移動・削除せずに残します。

### 3. Chromeへ登録する

1. Chromeのアドレスバーに `chrome://extensions` と入力し、Enterを押します。
2. 右上の **デベロッパーモード** をオンにします。
3. **パッケージ化されていない拡張機能を読み込む** をクリックします。
4. 展開した、**`manifest.json` が直接入っているフォルダ**を選びます。
5. 拡張機能一覧に **zeta-manager** が追加されれば登録完了です。

ZIPや `manifest.json` 単体は選びません。フォルダが二重になっている場合は、内側の `manifest.json` がある方を選んでください。

Chromeウェブストアからの導入ではないため、デベロッパーモードでの読み込みが必要です。[Chrome公式の手順](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked)も参照できます。

### 4. Zetaで確認する

Chromeで [Zeta](https://zeta-ai.io/) にログインし、プロットの会話ページを開きます。右側に **LIVE / ARCHIVES / SUMMARY / SETTINGS** が表示されれば導入完了です。

既に開いていたページは再読み込みしてください。トップページに会話用パネルが出ないのは正常です。

<a id="ios-install"></a>
## iOS版のインストール

iPhoneでは、Safariの機能拡張 **Userscripts** を通してzeta-managerを使います。パソコンやNode.jsは必要ありません。操作はZetaアプリではなく、Safari上のZetaで行います。

### 1. Userscriptsを準備する

1. App Storeから [Userscripts](https://apps.apple.com/app/id1463298887) をインストールします。
2. Userscriptsアプリを一度開きます。
3. スクリプトの保存先フォルダを確認します。既定の保存先が設定されていれば、そのまま使えます。保存先の指定を求められた場合は、使用するフォルダを選びます。

保存先は、次の手順でファイルを入れる場所です。アプリに表示される保存先をタップすると、「ファイル」アプリで確認できる版もあります。

### 2. zeta-managerのファイルを入れる

1. **Safariで** [iOS用ファイルをダウンロード](https://github.com/NakamuraShippo/zeta-manager/releases/latest/download/zeta-log-companion.user.js) を開きます。
2. ダウンロードの確認が出たら保存します。Rawボタンを探す必要はありません。
3. ダウンロードしたファイルを、「ファイル」アプリからUserscriptsの保存先へ移動します。共有メニューの **ファイルに保存** が使える場合は、その保存先を直接選んでも構いません。
4. 保存した名前が `zeta-log-companion.user.js` であることを確認します。

末尾に `.txt` や `.html` が付いたファイルでは動作しません。リンク先のスクリプトを保存してください。

リンク先でプログラムの文字列が表示された場合は、SafariのページメニューからUserscriptsを開き、インストール案内を使う方法もあります。詳細は [Userscripts公式の案内](https://github.com/quoid/userscripts#installation)を参照してください。

### 3. Safariで有効にする

1. iPhoneの **設定 → アプリ → Safari → 機能拡張** を開きます。
2. **Userscripts** を選び、有効にします。
3. Safariで [Zeta](https://zeta-ai.io/) を開きます。
4. アドレスバー付近のページメニューから **機能拡張 / Userscripts** を開きます。
5. Zetaへのアクセスを求められたら許可します。継続して使う場合は、このサイトへのアクセスを **常に許可** にします。
6. スクリプト一覧の**zeta-manager**が有効になっていることを確認します。
7. Zetaページを再読み込みします。

iOSの版によっては、設定の入口が **設定 → Safari** です。メニューの名称や位置が違う場合は [Apple公式の説明](https://support.apple.com/ja-jp/guide/iphone/iphab0432bf6/ios)も参照してください。

### 4. 会話ページで確認する

SafariでZetaにログインし、プロットの会話を開きます。左下の **zeta-manager** をタップして、会話テキストや **全履歴を同期 / コピー** が表示されれば導入完了です。

<a id="usage"></a>
## 会話ログの使い方

### 「@」の話者候補をキーボードで選ぶ

メッセージ入力欄に `@` を入力して話者候補を表示すると、次のキーが使えます。

| キー | 操作 |
| --- | --- |
| `→` / `←` | 候補を左右に移動。選択中の候補を枠で表示 |
| `Enter` | 矢印キーで選んだ候補を確定 |
| `1` | 先頭の候補（ナレーター）を直接選択 |
| `2`〜`9` | 表示順で2〜9番目の候補を直接選択 |
| `0` | 10番目の候補を直接選択 |

数字はキーボード上段とテンキーの両方に対応します。テンキーはNum Lockを有効にしてください。候補が10件を超える場合も矢印キーで移動できます。
入力欄から最初に `→` を押すと先頭、`←` を押すと末尾を選びます。確定後はメッセージ入力欄へ戻ります。
候補が閉じているときや日本語変換中は通常のキー操作を維持します。iOS版でも外付けキーボードで利用できます（実機未確認）。

### 普通にスクロールして取得する

読み進めるだけで、表示された会話を取り込みます。Chrome版の自動保存は **SETTINGS** で切り替えられます。

画面に読み込まれなかった区間は取得できません。スクロールバーで大きく飛ばした場合など、抜けが気になるときは次の全履歴同期を使ってください。

### 全履歴を同期する

**全履歴を同期** を押すと、過去ログを読み込み、上から下へスクロールしながら会話を取得します。処理中は会話を切り替えず、手動スクロールを避けて待ちます。終了後は元のスクロール位置へ戻ります。

「未完了」は全件の取得を確認できていない状態です。通信状態を確認して再実行してください。

### コピー・保存ログを使う

**コピー** で会話をクリップボードへ入れ、メモなどへ貼り付けられます。Chrome版の **ARCHIVES** では保存ログの一覧・閲覧・コピー・削除ができます。同じ会話・同じ日付のログは更新されます。

iOS版には保存ログ一覧の画面がありません。大切なログはコピーして別途残してください。

<a id="lorebook"></a>
## Markdownからロアブックを入力する

### ファイルを作る

[サンプルファイル](examples/lorebook.md)を参考に、UTF-8のテキストファイルを作り、`.md` という拡張子で保存します。メモ帳などを使う場合は、末尾が `.md.txt` にならないようにしてください。

```md
## 王都アルマ
キーワード: 王都、アルマ、首都

王国の中心に位置する都市。
中央には王城があり、周囲には商業区と居住区が広がる。

## 魔法学院
キーワード: 学院、魔法学院

魔術師を育成する教育機関。
入学には適性試験への合格が必要。
```

`## 題名` の次に `キーワード:` の行を書き、空行を挟んで内容を記述します。キーワードの区切りは `、` と `,` が使えます。本文中の小見出しには `### ` を使ってください。`## ` は別項目の開始として扱います。

### Zetaへ入力する

1. Zetaの設定集編集画面で、ロアブック欄を開きます。
2. **Markdownからロアブックを取り込む** を開き、作成した `.md` を選びます。
3. 読み取った内容を確認して **確認した内容を入力する** を押します。
4. 入力中は編集画面を操作せず待ちます。
5. Zeta上で入力結果を確認して、自分で登録します。

入力済み項目は保持します。題名・キーワード・内容がすべて空の項目から利用し、不足分を追加します。折りたたまれた項目は自動で展開します。

設定集全体の題名・紹介文の入力や、登録・完成ボタンの操作は対象外です。

| 入力内容 | 制限 |
| --- | --- |
| 題名 | 1〜20文字 |
| キーワード | 各1〜20文字、1〜5個 |
| 内容 | 1〜500文字 |
| 項目数 | 入力済み項目を含めて最大50件 |

文字数は入力欄に合わせて数え、絵文字などは2文字以上として扱う場合があります。制限を超えた文章は切り詰めず、エラーを表示します。中止・エラー時は入力した内容が残るため、再実行前に画面を確認してください。

## LLM要約について

**Chrome版のSUMMARYはデバッグ中・動作未保証です。** LLMへの接続、会話の送信、要約結果の取得を含めて確認中であり、利用できることを保証していません。

ローカルLLM・OpenAI互換API・Generic JSON HTTP向けの実装があります。試用する場合は **SETTINGS** で接続先・モデル・必要に応じたAPIキーを設定します。外部LLMへの送信には初回確認と接続先への権限許可が必要で、利用するサービス側で料金が発生する場合があります。

会話ログ管理とロアブック入力だけを使う場合、この設定は不要です。iOS版にLLM要約は含まれません。

<a id="update"></a>
## zeta-managerを更新する

### Chrome版

1. 必要なログをコピーして退避します。
2. [最新のChrome用ZIP](https://github.com/NakamuraShippo/zeta-manager/releases/latest/download/zeta-manager-chrome.zip)をダウンロードし、展開します。
3. 展開した中身を、Chromeに登録済みのフォルダへコピーして置き換えます。以前ビルドして導入した方は、そのときの `dist` が置き換え先です。再ビルドは不要です。
4. `chrome://extensions` で該当する拡張機能の **再読み込み（丸い矢印）** を押します。
5. Zetaページも再読み込みします。

登録先のフォルダの場所は変えません。更新のために拡張機能を削除すると、保存データを失うことがあるため、削除せずに更新してください。

### iOS版

新しい [iOS用ファイルをダウンロード](https://github.com/NakamuraShippo/zeta-manager/releases/latest/download/zeta-log-companion.user.js) を保存し、Userscriptsの保存先にある同名ファイルを置き換えます。その後、SafariのZetaページを再読み込みします。

古い版を別名で残して同時に有効にせず、更新した1つを使ってください。

<a id="troubleshooting"></a>
## 困ったときは

| 症状 | 確認すること |
| --- | --- |
| Node.jsやビルドを求められる | 上の「Chrome版をダウンロード」から完成済みZIPを取得すれば不要です。 |
| ZIPに `src` や `package.json` が入っている | ソースコードのZIPです。Assetsの `zeta-manager-chrome.zip` を取得してください。 |
| 展開後に `dist` がない | 配布ZIPでは `manifest.json` などが展開先に直接入ります。そのフォルダをChromeで選んでください。 |
| Chromeでマニフェストを読み込めない | `manifest.json` が直接入った展開済みフォルダを選びます。 |
| 会話パネルが出ない | 拡張機能を有効にし、Zetaの会話ページを再読み込みします。 |
| iPhoneで動かない | Safariで開いているか、Userscriptsの有効化・Zetaへのアクセス許可・保存先・ファイル名を確認します。 |
| Userscriptsにファイルが出ない | 指定した保存先に `.user.js` があるか確認します。iCloud上のファイルはダウンロード済みにしてください。 |
| 会話が抜ける・順序が気になる | 最新版へ更新し、「全履歴を同期」を実行します。取得できなかった本文を自動で復元することはできません。 |
| Zetaの表示が崩れる | Chrome版のSETTINGSで **Overlay** に戻し、ページを再読み込みします。Dockは実験的な表示モードです。 |
| Markdownの取り込み欄が出ない | 設定集の編集画面でロアブック欄を開きます。Zetaの画面構造が変わった場合は検出できなくなることがあります。 |
| LLM要約が動かない | 現在デバッグ中・動作未保証です。 |

問題を報告する場合は、利用端末・ブラウザ・操作手順・エラー表示を添えてください。会話本文やAPIキーは伏せてください。

## 保存データと外部通信

会話は利用中のブラウザ内に保存します。Chrome版は拡張機能のIndexedDB、iOS版はZetaのサイト領域のIndexedDBを使います。PCとiPhoneでデータは自動共有されません。サイトデータや拡張機能の削除などで保存内容を失う場合があるため、大切なログは別途コピーしてください。

会話の取得はページに表示された内容を読み取る方式です。Zetaの内部API・Cookie・認証情報を取得処理に使いません。Markdownもブラウザ内で読み取り、LLMには送信しません。入力後の内容はZetaの編集画面で扱われます。

LLM要約を試用する場合は、会話本文と必要なメタデータを設定した接続先へ送信します。APIキーは既定ではブラウザ終了時に破棄され、保存設定をオンにした場合のみ永続保存します。

## 開発・配布する方へ

以下はソースコードを変更する方向けです。通常のインストールには不要です。Node.jsのLTS版を導入し、package.jsonがあるフォルダで実行します。

```sh
npm ci
npm run typecheck
npm test
npm run build
```

開発中に変更を監視してビルドする場合は `npm run watch` を使います。

| 場所 | 内容 |
| --- | --- |
| `dist/` | Chrome用のビルド成果物。Git管理対象外 |
| `dist-mobile/` | iOS用ユーザースクリプトとブックマークレット |
| `src/content/` | 会話解析・スクロール取得・時系列管理・Chrome版パネル |
| `src/mobile/` | iOS版の起動処理とパネル |
| `src/lorebook/` | Markdown解析・入力処理・取り込みUI |
| `src/background/` | Chrome版の設定・保存・LLM通信 |
| `src/storage/` | IndexedDB・アーカイブ管理 |
| `src/llm/` | デバッグ中のLLM接続・要約処理 |
| `src/shared/` | 型・テキスト整形・共通処理 |
| `tests/` | 回帰テスト。会話HTMLのfixtureは合成データ |

会話の順序は画面上の位置と共通メッセージを使って接合します。再生成の非表示変種は履歴として保持し、部分同期の未走査分は既存の前後関係に沿って戻します。保存データの `index` はZetaの `data-index` ではなく、zeta-manager側の通し番号です。

DBはバージョン2です。バージョン1からの更新時には、順序の定義変更に伴って既存データを消去する処理があります。

配布前に型チェック・テスト・ビルドを実行してください。`dist` 直下の5ファイルをZIPの直下に格納し、`zeta-manager-chrome.zip` としてGitHub Releasesへ添付します。`dist-mobile/zeta-log-companion.user.js` も添付してください。最新リリースへのリンクを維持するため、添付ファイル名は固定します。

ページの再読み込みごとに実行が必要で、サイト側の制限によって動かないことがあります。通常はUserscripts方式を使ってください。

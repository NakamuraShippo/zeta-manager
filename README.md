# Zeta Log Companion

[Zeta Web版](https://zeta-ai.io/)の会話を取得・保存し、コピーやロアブックの一括入力ができる補助ツールです。

**パソコンではChrome版、iPhoneではSafariで動くiOS版を使います。** ZetaのWebページを開いて利用してください。

## できること

| 機能 | Chrome版（パソコン） | iOS版（Safari） |
| --- | :---: | :---: |
| スクロールで表示した会話の自動取得 | ○ | ○ |
| 全履歴を同期・会話をコピー | ○ | ○ |
| 会話の自動保存 | ○ | ○ |
| 保存ログの一覧・閲覧・削除 | ○ | — |
| LLMを使った要約 | ○ | — |
| Markdownからロアブックへ一括入力 | ○ | ○ |

会話の取得・コピー・ロアブック入力には、AIサービスのAPIキーは不要です。

<a id="chrome-install"></a>
## Chrome版のインストール

### 1. 必要なものを用意する

- WindowsまたはMacのパソコン
- Google Chrome
- [Node.js](https://nodejs.org/)のLTS版

Node.jsは、ダウンロードしたソースコードからChromeで読み込めるファイルを作るために使います。この作業を「ビルド」と呼びます。プログラムを書き換える必要はありません。

**このリポジトリではChrome用の `dist` フォルダをGitに含めていないため、GitHubからダウンロードした後にビルドが必要です。**

Node.jsの公式サイトでLTS版のインストーラーをダウンロードし、画面の案内に沿ってインストールしてください。インストール後、既に開いているコマンド画面があれば閉じます。

### 2. GitHubからファイルをダウンロードする

1. このリポジトリのトップページ（ファイル一覧がある画面）を開きます。
2. **Code** → **Download ZIP** をクリックします。
3. ダウンロードしたZIPを展開します。
   - Windows：ZIPを右クリック → **すべて展開**。
   - Mac：ZIPをダブルクリック。
4. 展開したフォルダを、ドキュメントなどの保管場所へ移します。
5. フォルダを開き、`package.json`、`build.mjs`、`src` が入っていることを確認します。

以降の手順では、この `package.json` があるフォルダを使います。ZIPを開いただけの状態では作業できないので、必ず展開してください。

### 3. Chrome用のファイルを作る

**Windowsの場合**

1. エクスプローラーで、`package.json` があるフォルダを開きます。
2. 上部のアドレスバー（フォルダの場所が表示される欄）をクリックします。
3. `cmd` と入力してEnterを押します。そのフォルダでコマンドプロンプトが開きます。

**Macの場合**

1. 「ターミナル」アプリを開きます。
2. `cd ` と入力します。`cd` の後ろに半角スペースを入れてください。
3. `package.json` があるフォルダをターミナルへドラッグし、Enterを押します。

開いた画面で、次のコマンドを**1行ずつ**入力し、Enterを押してください。1行目がエラーなく終了してから2行目を実行します。

```sh
npm ci
npm run build
```

1行目は必要な部品のダウンロードです。初回は少し時間がかかります。2行目が成功すると `build complete: dist/ , dist-mobile/` と表示され、`dist` フォルダができます。

### 4. Chromeへ読み込む

1. Chromeのアドレスバーに `chrome://extensions` と入力し、Enterを押します。検索欄ではなく、URLを入力する欄です。
2. 右上の **デベロッパーモード** をオンにします。
3. **パッケージ化されていない拡張機能を読み込む** をクリックします。
4. 手順3でできた **`dist` フォルダ**を選択します。
5. 拡張機能一覧に **Zeta Log Companion** が表示されれば導入完了です。

選ぶのは、`manifest.json` と `content.js` が入っている `dist` フォルダです。プロジェクト全体のフォルダや、`manifest.json` 単体を選ばないでください。

導入後も `dist` フォルダは使います。移動したり削除したりせず、その場所に残してください。

読み込み操作については、[Chrome公式の説明](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked)も参照できます。

### 5. 動作を確認する

1. Chromeで [Zeta](https://zeta-ai.io/) にログインします。
2. プロットの会話ページを開きます。既に開いていた場合は再読み込みします。
3. 右側に **LIVE / ARCHIVES / SUMMARY / SETTINGS** のパネルが出れば動いています。

トップページに会話用パネルが出ないのは正常です。ロアブックの入力機能は、設定集の編集画面で表示されます。

<a id="ios-install"></a>
## iOS版のインストール

iPhoneでは **Safari＋Userscripts** を使います。Userscriptsは、Safariのページ上で補助プログラムを動かすためのアプリです。パソコンやNode.jsは必要ありません。

### 1. Userscriptsを入れる

1. App Storeで [Userscripts](https://apps.apple.com/app/id1463298887) をインストールします。
2. Userscriptsアプリを一度開きます。
3. スクリプトの保存先フォルダを確認します。現在の版では初回起動時に既定のフォルダが設定されます。保存先の指定を求められる版では、使用するフォルダを選んでください。

次の手順で、このフォルダへファイルを入れます。保存場所が分からない場合は、アプリに表示される保存先をタップして「ファイル」アプリで確認してください。

### 2. iOS用ファイルを保存する

1. **Safariで**このGitHubページを開きます。
2. [iOS用ファイル：zeta-log-companion.user.js](dist-mobile/zeta-log-companion.user.js) を開きます。
3. GitHubのファイル画面で **Raw** または **Download raw file** を探します。スマートフォンでは「…」メニュー内にある場合があります。
4. ファイルをダウンロードし、「ファイル」アプリからUserscriptsの保存先フォルダへ移動します。共有メニューから **ファイルに保存** が選べる場合は、直接そのフォルダへ保存しても構いません。
5. 名前が **`zeta-log-companion.user.js`** になっていることを確認します。末尾に `.txt` や `.html` が付いたファイルは使えません。

Rawを開いてプログラムの文字列が表示された場合は、そのままSafariのページメニューからUserscriptsを開き、表示されるインストール案内を使う方法もあります。GitHubの通常のファイル表示画面ではなく、Rawの画面で行ってください。

ファイル保存とRawからの導入は、[Userscripts公式のインストール案内](https://github.com/quoid/userscripts#installation)で説明されています。

### 3. Safariで有効にする

1. iPhoneの **設定** → **アプリ** → **Safari** → **機能拡張** を開きます。
2. **Userscripts** を選び、有効にします。
3. Safariで [Zeta](https://zeta-ai.io/) を開きます。
4. アドレスバー付近のページメニューから **機能拡張 / Userscripts** を開きます。
5. Zetaへのアクセス許可を求められたら許可します。継続して使う場合は、このサイトへのアクセスを **常に許可** にします。
6. Userscripts内で **Zeta Log Companion Mobile** が有効になっていることを確認し、Zetaページを再読み込みします。

iOSのバージョンによっては設定の入口が **設定 → Safari** です。メニュー名やアイコンの位置も異なる場合があります。[Apple公式の機能拡張の説明](https://support.apple.com/ja-jp/guide/iphone/iphab0432bf6/ios)も参照してください。

### 4. 動作を確認する

1. Safari上でZetaにログインし、プロットの会話ページを開きます。
2. 左下の **ZETA LOG** ボタンをタップします。
3. 会話テキストや **全履歴を同期 / コピー** が表示されれば導入完了です。

Zetaアプリへ切り替えず、SafariのWebページで使ってください。

<a id="usage"></a>
## 会話ログの使い方

### 読み進めながら取得する

会話ページを普通にスクロールすると、表示された範囲を自動で取得します。遅れて読み込まれた会話も追加されます。Chrome版の自動保存は **SETTINGS** で切り替えられます。

スクロールバーで一気に飛ばし、ブラウザが読み込まなかった区間は取得できません。

### 過去の会話をまとめて取得する

**全履歴を同期** を押すと、過去ログを読み込み、上から下へ自動でスクロールしながら取得します。処理中はそのページで待ち、会話の切り替えや手動スクロールを避けてください。

終了後は元のスクロール位置へ戻ります。「未完了」と表示された場合は、全件の取得を確認できていません。通信状態を確認して再実行してください。

### コピー・保存ログ・要約

- **コピー**：会話をコピーして、メモなどへ貼り付けられます。
- **ARCHIVES（Chrome版）**：保存ログの一覧、閲覧、コピー、削除ができます。同じ会話・同じ日付のログは更新されます。
- **SUMMARY（Chrome版）**：LLMによる要約を作れます。利用するサービスの接続先・モデル・必要に応じたAPIキーを **SETTINGS** に設定してください。外部サービス側で料金が発生する場合があります。

ローカルLLMとOpenAI互換API、Generic JSON HTTPに対応しています。外部LLMへの要約送信では初回確認と接続先への権限許可が必要です。要約を使わなければ、LLMの設定は不要です。

<a id="lorebook"></a>
## Markdownでロアブックを入力する

Chrome版・iOS版の両方で使えます。[サンプルファイル](examples/lorebook.md)を参考に、UTF-8のテキストファイルを作り、拡張子を `.md` にして保存してください。メモ帳などで作る場合、末尾が `.md.txt` にならないようにします。

```md
## 王都アルマ
キーワード: 王都、アルマ、首都

王国の中心に位置する都市。
中央には王城があり、周囲には商業区と居住区が広がる。

## 魔法学院
キーワード: 学院、魔法学院

魔術師を育成する教育機関。
入学には適性試験への合格が必要。
```

1. Zetaで設定集の編集画面を開きます。
2. ロアブック欄に表示される **Markdownからロアブックを取り込む** を開きます。
3. `.md` ファイルを選び、読み取った一覧を確認します。
4. **確認した内容を入力する** を押し、操作せずに待ちます。
5. Zeta上で入力結果を確認し、自分で登録します。

入力済み項目は保持し、題名・キーワード・内容がすべて空の項目を利用します。不足分は自動で追加し、折りたたまれた項目は展開します。設定集全体の題名・紹介文や、登録・完成ボタンは操作しません。

| 項目 | 制限 |
| --- | --- |
| 題名 | 1〜20文字 |
| キーワード | 各1〜20文字、1〜5個 |
| 内容 | 1〜500文字 |
| 項目数 | 入力済み項目を含めて最大50件 |

キーワードは `、` または `,` で区切ります。`## ` は次の項目の開始なので、本文中の小見出しには `### ` を使います。文字数は入力欄に合わせて数え、絵文字などは2文字以上となる場合があります。

超過した文章は切り捨てず、エラーを表示します。中止・エラー時は既に入力した内容が残るため、再実行前に画面を確認してください。

<a id="update"></a>
## 更新方法

### Chrome版

1. 大切な会話ログをコピーして退避します。
2. 新しいソースコードをダウンロード・展開し、[インストール手順](#chrome-install)と同様に `npm ci` → `npm run build` を実行します。
3. 新しくできた `dist` の中身を、Chromeに登録済みの `dist` フォルダへコピーして置き換えます。別の場所でビルドした場合も、登録先フォルダの場所は変えません。
4. `chrome://extensions` を開き、Zeta Log Companionの **再読み込み（丸い矢印）** を押します。
5. Zetaのページも再読み込みします。

更新のために拡張機能を削除する必要はありません。拡張機能を削除すると保存データを失うことがあります。

### iOS版

1. 新しい `zeta-log-companion.user.js` をダウンロードします。
2. Userscriptsの保存先にある同名ファイルを置き換えます。
3. 古い版と新しい版を別名で同時に有効にせず、更新した1つだけを使います。
4. SafariでZetaページを再読み込みします。

<a id="troubleshooting"></a>
## 困ったときは

| 症状 | 確認すること |
| --- | --- |
| `npm` が見つからない | Node.jsのインストール後、コマンド画面を開き直してください。 |
| `package.json` が見つからないエラー | コマンドを実行したフォルダが違います。ZIPを展開し、`package.json` のあるフォルダで実行してください。 |
| `dist` フォルダがない | `npm ci` と `npm run build` が成功したか確認してください。GitHubのZIPには最初から含まれません。 |
| Chromeでマニフェストを読み込めない | `manifest.json` が入っている `dist` フォルダを選んでください。 |
| Chromeのパネルが出ない | 拡張機能が有効か確認し、Zetaの会話ページを再読み込みしてください。 |
| iPhoneでZETA LOGが出ない | Safariで会話ページを開いているか、Userscriptsの有効化・サイトへのアクセス許可・保存先・ファイル名を確認してください。 |
| Userscriptsにファイルが出ない | 保存先が違うか、末尾に `.txt` が付いていないか確認してください。iCloud上のファイルは「ファイル」アプリでダウンロード済みにしてください。 |
| 会話が抜ける・順序が気になる | 最新版に更新し、「全履歴を同期」を実行してください。既に取得できなかった本文を自動で復元することはできません。 |
| Zetaの表示が崩れる | Chrome版のSETTINGSで表示モードを **Overlay** に戻し、ページを再読み込みしてください。Dockは実験的なモードです。 |
| ロアブックの取り込み欄が出ない | 設定集の編集画面でロアブック欄を開いてください。Zeta側の画面構造変更で検出できなくなる場合もあります。 |

解決しない場合は、利用端末・ブラウザ・操作手順・エラー表示を添えて報告してください。会話本文やAPIキーは伏せてください。

<a id="data"></a>
## 保存データと外部通信

- 会話は利用中のブラウザ内に保存します。Chrome版は拡張機能のIndexedDB、iOS版はZetaのサイト領域のIndexedDBを使います。PCとiPhoneのデータは自動共有されません。
- iOS版には保存ログ一覧の画面がありません。大切なログはコピーして別途残してください。
- ブラウザのサイトデータ削除や拡張機能の削除などで保存内容を失う場合があります。
- Zetaの内部API・Cookie・認証情報を取得処理に使わず、Webページに表示された会話を読み取ります。
- LLM要約を使うと、会話本文と必要なメタデータが指定した接続先へ送信されます。APIキーは既定ではブラウザ終了時に破棄され、保存設定をオンにした場合のみ永続保存します。
- Markdownファイルはブラウザ内で読み取り、LLMへは送信しません。入力後の内容はZetaの編集画面で扱われます。

<a id="development"></a>
## 開発者向け情報

```sh
npm ci
npm run typecheck
npm test
npm run build
npm run watch
```

| 場所 | 内容 |
| --- | --- |
| `dist/` | Chrome用ビルド成果物（Git管理対象外） |
| `dist-mobile/` | iOS用ユーザースクリプトとブックマークレット |
| `src/content/` | DOM解析・スクロール取得・時系列管理・PCパネル |
| `src/mobile/` | モバイル版の起動処理とパネル |
| `src/lorebook/` | Markdown解析・編集フォームへの入力・取り込みUI |
| `src/background/` | Chrome版の保存・設定・LLM通信 |
| `src/storage/` | IndexedDBとアーカイブ管理 |
| `src/llm/` | Provider実装・長文の分割要約 |
| `src/shared/` | 型・テキスト整形・共通処理 |
| `tests/` | 回帰テスト。会話HTMLのfixtureは合成データ |

会話の順序は画面上の位置と共通メッセージのアンカーで接合します。再生成の非表示変種は履歴として保持し、全履歴同期の未走査分は既存の前後関係に沿って復元します。保存データの `index` はZetaの `data-index` ではなく、ツール側の通し番号です。

DBはバージョン2です。バージョン1からの更新時は順序の定義が変わるため、既存データを消去する実装があります。保存処理を変更する際はこの移行処理も確認してください。

配布時は `npm run build` でPC・モバイル両方を更新してください。初心者向けにビルド済みChrome版を配布する場合は、`dist` の中身をZIPにしてGitHub Releasesへ添付すると、利用者のNode.js導入・ビルド作業を省けます。

<details>
<summary>iOS向けの代替手段：ブックマークレット</summary>

`dist-mobile/bookmarklet.txt` にある `javascript:` から始まる1行を、SafariのブックマークのURL欄へ貼り付けます。Zetaのページを開いてそのブックマークを実行すると起動します。

ページを再読み込みするたびに実行が必要で、サイト側の制限によって動かない場合があります。通常は上記のUserscripts方式を使ってください。

</details>
